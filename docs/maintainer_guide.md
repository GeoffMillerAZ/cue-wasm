# Maintainer guide

This is already an independent repository. Start with [intent](intent/README.md),
[roadmap](roadmap.md) and the [current tracker](tracking/implementation_tracker.md).
Do not repeat the historical extraction or create another repository.

## Source and prepared packages

- Go source: main.go and internal/core. Go1.24.4 and CUE0.15.4 are the current pins.
- JavaScript/types: internal/js and internal/react. dist is generated, never hand-edited.
- Prepared assets: bin, generated by build.sh with the matching Go shim and manifest.
- Prepared npm consumers need neither Go nor a sibling checkout. Contributors rebuilding
  WASM need the pinned Go toolchain; GOTOOLCHAIN may download it if absent.
- Source checkout bin is ignored. Run npm run build:wasm before package/semantic tests.
  No ambient wasm-opt is used. Evaluate optimizers separately with fixed versions,
  semantic tests and end-to-end measurements before changing release flags.

## Local verification

Follow README commands. npm test covers JS lifecycle, examples, narrow security
regressions and installed archive closure. test:semantic adds native/WASM comparisons.
Run the browser fixture separately. The React hook harness does not prove actual React
mounting. Node matrix/CI configuration is not evidence that remote CI ran.

Local pre-push is installed with lefthook install. It runs generated/intent/native/
package/semantic gates and Fathom plan claims. Missing Fathom fails loudly. Open tasks
are not certified by a passing claim gate. Fathom failures never replace runtime tests.

## Package and release

First prepare a clean checkout, run the gates, check binary manifest and npm pack
contents, and verify an independently installed consumer. Compare Go/CUE/package
versions separately. Rebuild twice and compare manifests when changing build inputs.
Keep migrations and CHANGELOG current; this uplift changes worker/validation behavior
and must not be silently released under the existing 1.4.5 version.

Release needs explicit owner authorization. Existing tag-triggered CI publishes; do not
push tags as part of routine local verification. Credentials belong in the CI secret
store, never source or package. No publish or new tag is authorized by local build work.

## Evidence and resources

Retain small manifests, exact commands, source identity and failure receipts. Do not
retain repeated binary copies or test node_modules; package smoke removes its scratch.
Keep benchmarks and support claims scoped to actually measured workloads/environments.
See [performance](performance_guide.md), [security](../SECURITY.md), and
[Fathom integration](design/fathom-integration.md).
